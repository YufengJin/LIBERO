# LIBERO — Benchmark Guide

Generated by `benchmark-env-generator` skill. English-only by contract; regenerated on every re-run.

## About

LIBERO (Lifelong Robot Learning Benchmark) is a simulation benchmark for knowledge transfer in lifelong decision-making for robots. It ships 130 manipulation tasks across five suites (`libero_spatial`, `libero_object`, `libero_goal`, `libero_10`, `libero_90`), plus human tele-operated demonstration datasets, and is built on top of `robosuite 1.4.0` + MuJoCo. The benchmark is designed for imitation learning and lifelong / continual learning research — not reinforcement learning — so rewards are sparse success indicators (`done=True` at task success) and the repo's `libero/lifelong/` module implements BC, EWC, PackNet, LwF and related algorithms rather than PPO/SAC.

| Field | Value |
|-------|-------|
| Simulator | `robosuite 1.4.0` (MuJoCo) |
| Benchmark category | **IL** (imitation / lifelong, no shaped reward) |
| Upstream paper / project | [libero-project.github.io](https://libero-project.github.io/) · arXiv 2306.03310 |
| License | MIT (see `LICENSE`) |
| Primary use case | Behavior cloning, lifelong / continual imitation learning, demonstration-based policy research |

## Tasks

The benchmark exposes **130** tasks total, grouped into five suites. Each suite shares a theme (object layout, object identity, task goal, length-10 mix, length-90 mix); within a suite each task has its own BDDL file under `libero/libero/bddl_files/<suite>/`. Pick a task by combining `--task_suite_name <suite>` with `--task_id <index>` in `scripts/run_demo.py` / `scripts/run_eval.py`.

| Suite | `--task_suite_name` | Task count | Max steps (client cap) | Example task |
|-------|---------------------|------------|------------------------|--------------|
| Spatial | `libero_spatial` | 10 | 220 | `pick up the black bowl between the plate and the ramekin and place it on the plate` |
| Object | `libero_object` | 10 | 280 | `pick_up_the_alphabet_soup_and_place_it_in_the_basket` |
| Goal | `libero_goal` | 10 | 300 | `open_the_middle_drawer_of_the_cabinet` |
| Libero-10 | `libero_10` | 10 | 520 | `KITCHEN_SCENE3_turn_on_the_stove_and_put_the_moka_pot_on_it` |
| Libero-90 | `libero_90` | 90 | 400 | `LIVING_ROOM_SCENE_n_*` series, broad coverage |

Max-step caps are client-side (see `TASK_MAX_STEPS` in `scripts/run_eval.py`); the env itself does not impose an episode horizon. Task identifiers are 0-indexed within each suite — use `task_suite.get_task(task_id).bddl_file` to resolve the actual BDDL filename.

### Task groups

- `libero_spatial` — same objects, different spatial layouts. Tests spatial generalization.
- `libero_object` — different objects, same spatial layout. Tests object-identity generalization.
- `libero_goal` — same scene, different goal predicates. Tests task-semantic generalization.
- `libero_10` — ten long-horizon tasks blending all three axes, used as a harder eval set.
- `libero_90` — 90-task continual-learning curriculum (primary benchmark for lifelong methods).

## Action / Observation spaces

| Field | Value |
|-------|-------|
| Action dim | `7` (OSC_POSE / cartesian_pose, default) · `8` (joint_vel / DROID-style, opt-in via `--arm_controller joint_vel` + `--droid` on the test server) |
| Action semantics | 6-D end-effector delta pose (xyz + rpy) + 1-D gripper (−1 = close, +1 = open) for OSC_POSE; 7-D joint velocities + 1-D gripper for joint_vel. Always float, action space clipped to ±1 per dim. |
| Observation type | Dict: `agentview_image` (HxWx3 RGB), `robot0_eye_in_hand_image` (HxWx3), `robot0_eef_pos` (3,), `robot0_eef_quat` (4,), `robot0_gripper_qpos` (2,), plus joint positions via `enable_joint_pos_observable` helper. |
| Control frequency | 20 Hz (robosuite default) |
| Reward signal | Sparse: `0.0` every step, `1.0` only on the step that flips `done=True` (task success). No shaping. |

## How to use

The skill produced three receipt files at the repo root — `install.md` (how to build), `history.md` (what the skill did), and this file (what the benchmark *is*). The flow below assumes you have already followed `install.md` and have a running container.

### 1. Enter the container

```bash
docker compose -f docker/docker-compose.headless.yaml up -d
docker exec -it libero_container bash
```

### 2. Pick a task

```bash
# List available tasks for a suite (0-indexed)
python -c "
from libero.libero import benchmark
for suite in ['libero_spatial', 'libero_object', 'libero_goal', 'libero_10', 'libero_90']:
    ts = benchmark.get_benchmark_dict()[suite]()
    print(f'=== {suite} ({ts.n_tasks} tasks) ===')
    for i in range(ts.n_tasks):
        print(f'  [{i}] {ts.get_task(i).language}')
"
```

Any `(suite, task_id)` pair from the listing is a valid `--task_suite_name <suite> --task_id <id>` combo.

### 3. Stand up a policy server

For a smoke test, use the companion random-policy server (ships with the image):

```bash
python tests/test_random_policy_server.py --port 8000               # action_dim=7 (cartesian_pose)
python tests/test_random_policy_server.py --port 8000 --droid       # action_dim=8 (joint_vel)
```

For real evaluation, replace it with any server that speaks the `policy_websocket` protocol and advertises `action_dim=7` (or `8`) in its metadata handshake — the client's guard in `scripts/run_eval.py` enforces the match.

### 4. Run a single-episode demo

```bash
python scripts/run_demo.py --policy_server_addr localhost:8000 \
    --task_suite_name libero_spatial --task_id 0 --num_resets 1 \
    --arm_controller cartesian_pose
```

This is the "show me one rollout" entry point — per-step inference log, optional GUI (`--gui` on the `x11` profile), and (headless default) MP4 written under `./demo_log/<suite>--<timestamp>/`.

### 5. Run multi-episode eval

```bash
python scripts/run_eval.py --policy_server_addr localhost:8000 \
    --task_suite_name libero_spatial --num_trials_per_task 10 \
    --arm_controller cartesian_pose
```

Iterates every task in the suite × `--num_trials_per_task` rollouts each. Prints rolling success rate per task and a final per-task / overall summary. `--save_video` (default off) writes one MP4 per episode into `./eval_logs/<suite>--<timestamp>/`; `--no_save_video` skips the writer for fast smoke runs.

### 6. Train / collect demonstrations

For behavior cloning on LIBERO you will typically:

1. Download the official demonstrations: `python benchmark_scripts/download_libero_datasets.py --use-huggingface`.
2. Train with the in-tree lifelong pipeline: `python libero/lifelong/main.py benchmark_name=LIBERO_SPATIAL algo=BC` (see `libero/configs/` for Hydra configs covering BC, EWC, LwF, PackNet, ER).
3. Wrap the trained policy in a `policy_websocket`-speaking server (mirror `tests/test_random_policy_server.py` — replace `RandomPolicy.infer` with your model forward pass).
4. Point `scripts/run_eval.py --policy_server_addr host:port` at that server to measure success rate.

The skill does **not** generate a training script for IL benchmarks — BC training code is benchmark-specific and LIBERO already ships `libero/lifelong/main.py` as the official entry point.

## Troubleshooting

- `ConnectionRefused` on `run_eval.py` → no policy server on the configured port. Start `tests/test_random_policy_server.py` first, or check the server process logs (`docker exec libero_container ps aux | grep policy`).
- `ValueError: server action_dim=X, expected Y` → policy server advertises a different action dim than the client expects. Either switch the client's `--arm_controller` (cartesian_pose = 7, joint_vel = 8) or start the server with the matching `--droid` flag.
- Task name not recognised → suite names are case-sensitive (`libero_spatial`, not `Libero_Spatial`); `--task_id` must be in range `[0, task_suite.n_tasks)`.
- GUI apps fail with `cannot open display` → you are on the headless compose profile. Switch to `docker-compose.x11.yaml` after `docker compose down`.
- `[Warning]: datasets path ... does not exist` on every env construction → harmless when running the random-policy smoke test; fix by running `python benchmark_scripts/download_libero_datasets.py --use-huggingface` once.
- Interactive config prompt (`Do you want to specify a custom path for the dataset folder?`) on `import libero.libero` → the container's `LIBERO_CONFIG_PATH` is unset. Re-create via `docker compose up -d` (compose sets `LIBERO_CONFIG_PATH=/workspace/.libero` in the env). Manual override: `docker exec -e LIBERO_CONFIG_PATH=/workspace/.libero libero_container ...`.
