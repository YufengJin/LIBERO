# LIBERO — Install Recipe

Minimum commands to reproduce this benchmark container from a fresh clone. Generated by `benchmark-env-generator` skill (sub-skill of `env-generator`).

## Host prerequisites

- Docker (>= 24) and the Compose v2 plugin
- NVIDIA driver + NVIDIA Container Toolkit with a GPU visible to `nvidia-smi`
- Disk budget for first-run asset download (LIBERO datasets are fetched on demand from Hugging Face; entrypoint prompts rather than force-downloads)

## Build the image

```bash
docker compose -f docker/docker-compose.headless.yaml build
```

Base image: `nvidia/cuda:11.8.0-cudnn8-runtime-ubuntu20.04`
Python: `3.8` (managed by `uv`)
Third-party simulator pinned: `robosuite @ 1.4.0`

## Bring the container up

```bash
docker compose -f docker/docker-compose.headless.yaml up -d
docker exec -it libero_container bash
```

For an X11 / GUI session (swap the compose profile — container name is shared, only one may run):

```bash
xhost +local:docker
docker compose -f docker/docker-compose.x11.yaml up -d
```

## First-run sanity checks (inside the container)

```bash
nvidia-smi
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
python -c "import libero.libero; print(libero.libero.__file__)"
```

The last line must resolve under `/workspace/libero/` — that proves the mounted source is what the interpreter imports (editable install succeeded).

### Interactive config handled automatically

`entrypoint.sh` writes `/workspace/.libero/config.yaml` before the first editable install so `import libero.libero` does not block on an interactive prompt. The compose file sets `LIBERO_CONFIG_PATH=/workspace/.libero` so every `docker exec` shell inherits the same config path — no user action needed.

### Optional asset / dataset download

The entrypoint prompts rather than force-downloads. Inside the container, run:

```bash
python benchmark_scripts/download_libero_datasets.py --use-huggingface
```

Datasets are only required for training / evaluating trained policies — the smoke test below runs the random-policy loop without them.

## Category-specific smoke run

### IL: WebSocket random-policy loop

The generated image ships with a companion server so the stack is end-to-end runnable without a trained policy:

```bash
# Start the random-policy server (advertises action_dim=7 for cartesian_pose; use --droid for 8-D joint_vel)
docker exec -d libero_container python tests/test_random_policy_server.py --port 8000

# Wait for the port
docker exec libero_container python -c "import socket, time, sys
for _ in range(30):
    s = socket.socket()
    try: s.connect(('127.0.0.1', 8000)); s.close(); print('ready'); sys.exit(0)
    except OSError: s.close(); time.sleep(0.2)
sys.exit('server not up')"

# Single-episode demo (saves MP4 to demo_log/)
docker exec libero_container python scripts/run_demo.py \
    --policy_server_addr localhost:8000 \
    --task_suite_name libero_spatial --task_id 0 --num_resets 1 \
    --arm_controller cartesian_pose

# Eval harness (iterates all tasks in the suite, N trials each)
docker exec libero_container python scripts/run_eval.py \
    --policy_server_addr localhost:8000 \
    --task_suite_name libero_spatial --num_trials_per_task 1 \
    --arm_controller cartesian_pose --no_save_video

# Clean up
docker exec libero_container pkill -f test_random_policy_server
```

The random policy never solves the task — a zero success rate plus a clean exit is the expected outcome.

## Stop / clean up

```bash
docker compose -f docker/docker-compose.headless.yaml down
```
